## LAKE-060 — Metadata and structured data

**Status:** open · **Phase:** MVP/M6 · **Parallel:** yes

**Objective:** REQ-SEO-01 core: localized titles/descriptions/OG cards and JSON-LD (`TouristAttraction`, `BreadcrumbList`, `WebSite`) generated from domain data, with the fresh-hours-only rule.

**User story:** As a tourist googling "Burg Meersburg öffnungszeiten", I should land on our verified, current page — that query class is the acquisition engine.

**Context:** [analytics-and-seo.md#seo](../../operations/analytics-and-seo.md#seo) (binding rules incl. stale-hours exclusion from JSON-LD), OQ-1 (domain — placeholder acceptable, canonical config env-driven).

**In scope:** metadata generation per route (localized titles ≤60 chars, descriptions from summaries ≤155, length-linted); OG/Twitter cards (licensed images only; category placeholder as OG fallback); JSON-LD: `TouristAttraction` (geo, address, openingHoursSpecification **only when hours fresh**, priceRange, isAccessibleForFree, sameAs official+Wikidata), `BreadcrumbList`, `WebSite`+`SearchAction`; canonical URLs (filter params excluded on list); `noindex` verification for admin/shared-plans/legal drafts; Lighthouse SEO budget activated.
**Out of scope:** sitemaps/hubs (LAKE-061), hreflang (done in LAKE-025 — verified here).

**Dependencies:** LAKE-040, LAKE-025, LAKE-055 (freshness levels for the JSON-LD rule). **Files:** metadata modules per route, JSON-LD builders in a small lib, length lint.

**Domain rules:** JSON-LD from the same projections as the page (no drift — shared builder test); stale hours never serialized as fact.
**API changes:** none. **DB changes:** none.
**UI states:** n/a (head-level). **DE/EN:** all meta localized; hreflang triple verified.
**A11y:** n/a. **Privacy/security:** no user data in meta; OG images licence-checked (registry-backed only).

**Acceptance criteria:**
- [ ] Rich-results validation passes for fixture detail pages (both locales)
- [ ] Stale-hours fixture omits openingHoursSpecification; fresh includes it
- [ ] Length lints active; canonical/noindex matrix verified by tests
- [ ] Lighthouse SEO ≥ target on core pages

**Tests:** Unit: builders (drift test vs projection). Integration: meta rendering matrix. E2E: none new.
**Manual validation:** Google Rich Results test on staging URLs.
**Commands:** `pnpm test -g seo`.
**Rollback:** meta-only changes; revert safe.

## LAKE-061 — Sitemaps and region hubs

**Status:** open · **Phase:** MVP/M6 · **Parallel:** yes

**Objective:** Localized XML sitemaps (daily job) and the nine region hub pages interlinking attractions.

**User story:** As a search engine, I want a complete, current URL inventory; as a visitor landing on "Untersee attractions", I want a useful regional overview.

**Context:** [analytics-and-seo.md](../../operations/analytics-and-seo.md#seo), region model from [geographic-scope.md](../../product/geographic-scope.md#product-regions).

**In scope:** sitemap generation job (localized sitemaps + index: attractions, guides, hubs, static; excludes admin/shared/noindex; lastmod from content updates) on the LAKE-051 slot; robots.txt; region hub pages `/{locale}/regionen/{code}|regions/{code}` (localized region intro — written DE+EN in this ticket, attraction grid by relevance, map snippet via abstraction, links into filtered Discover); hub linking from More/footer and Discover region filter.
**Out of scope:** editorial region-content depth beyond a solid intro paragraph (extendable later).

**Dependencies:** LAKE-051 (job), LAKE-060, LAKE-028 (region queries). **Files:** sitemap job, robots, hub routes + content.

**Domain rules:** hubs list published attractions only; region codes stable in URLs.
**API changes:** none. **DB changes:** none.
**UI states:** hub with few attractions gets honest "growing coverage" note (pre-full-research reality).
**DE/EN:** hub intros written bilingually (original content, review-checklist rules apply).
**A11y:** hub structure semantic; grid = list semantics.
**Privacy/security:** sitemap excludes capability URLs (test).

**Acceptance criteria:**
- [ ] Sitemap index + localized maps valid (validator), complete vs fixture inventory, regenerated by job
- [ ] Shared-plan/admin URLs absent (test); robots.txt sane
- [ ] All nine hubs render bilingually with correct attraction sets and Discover links

**Tests:** Integration: sitemap content matrix. E2E: hub rendering + navigation.
**Manual validation:** submit staging sitemap to a validator.
**Commands:** `curl … /api/jobs/sitemap`.
**Rollback:** hubs/routes removable; sitemap regenerates.
